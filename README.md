# Deploying the TravelMemory MERN Application on AWS with Terraform and Ansible

This repository contains the infrastructure-as-code and configuration management used to deploy the [TravelMemory](https://github.com/UnpredictablePrashant/TravelMemory) MERN stack application (MongoDB, Express, React, Node.js) on AWS.

- **Terraform** provisions the AWS network, security groups, IAM role and two EC2 instances.
- **Ansible** configures the servers, installs MongoDB, deploys the app and hardens the hosts.

## Architecture

```
                         Internet
                            |
                     [Internet Gateway]
                            |
 +--------------------- VPC 10.0.0.0/16 ----------------------+
 |                                                            |
 |  Public subnet 10.0.1.0/24                                 |
 |    - Web EC2 (nginx + React build, Express/Node via pm2)   |
 |    - NAT Gateway (+ Elastic IP)                            |
 |    - Ansible control node (the web EC2 itself)             |
 |                         |                                  |
 |                         | MongoDB 27017 / SSH 22           |
 |                         v                                  |
 |  Private subnet 10.0.2.0/24                                |
 |    - DB EC2 (MongoDB, auth enabled, no public IP)          |
 |      outbound internet via NAT Gateway                     |
 +------------------------------------------------------------+
```

### How the components interact

1. The browser requests `http://<WEB_PUBLIC_IP>/`. nginx serves the React production build from `/var/www/html`.
2. The React frontend calls the Express backend at `http://<WEB_PUBLIC_IP>:3001` (configured in `frontend/src/url.js`).
3. The Express backend, managed by pm2, connects to MongoDB on the DB server's private IP (port 27017) using credentials from its `.env` file.
4. The DB server has no public IP. It is reachable only from the web server's security group, and reaches the internet (for package installs) through the NAT Gateway.
5. Ansible runs from the web EC2 inside the VPC, so it reaches the DB server over its private IP using SSH agent forwarding.

## Prerequisites

- Windows 11 with PowerShell
- AWS account and IAM access keys with permission to create VPC, EC2, IAM and EIP resources
- Installed locally: AWS CLI, Terraform, Git

```powershell
winget install Amazon.AWSCLI Hashicorp.Terraform Git.Git
aws configure
aws sts get-caller-identity
```

## Part 1: Infrastructure with Terraform

```powershell
cd terraform

# Restrict SSH to your public IP
$ip = (Invoke-RestMethod https://checkip.amazonaws.com).Trim()
"my_ip = `"$ip/32`"" | Out-File -Encoding ascii terraform.tfvars

terraform init
terraform plan
terraform apply
```

Resources created:

| Resource        | Details                                                                               |
| --------------- | ------------------------------------------------------------------------------------- |
| VPC             | 10.0.0.0/16                                                                           |
| Subnets         | Public 10.0.1.0/24, private 10.0.2.0/24                                               |
| Gateways        | Internet Gateway, NAT Gateway with Elastic IP (in the public subnet)                  |
| Route tables    | Public routes to IGW, private routes to NAT                                           |
| Key pair        | Generated by Terraform, saved locally as `terraform/mern-key.pem`                     |
| Security groups | Web: SSH from your IP only, HTTP 80, API 3001. DB: SSH and 27017 from the web SG only |
| IAM             | EC2 role with SSM and CloudWatch agent policies, attached via instance profile        |
| EC2             | Two Ubuntu instances: web (public subnet) and database (private subnet)               |

Outputs: `web_public_ip` and `db_private_ip`.

## Part 2: Configuration and deployment with Ansible

Ansible runs from the web EC2.

**1. Connect from Windows with agent forwarding**

```powershell
Start-Service ssh-agent
icacls terraform\mern-key.pem /inheritance:r /grant:r "$($env:USERNAME):R"
ssh-add .\terraform\mern-key.pem
ssh -A ubuntu@<WEB_PUBLIC_IP>
```

**2. On the EC2 instance**

```bash
sudo apt update && sudo apt install -y ansible git tmux
git clone https://github.com/rahulchidambaram/TravelMemory.git
cd TravelMemory/ansible
```

**3. Set the DB private IP in the inventory**

```bash
sed -i 's/<DB_PRIVATE_IP>/10.0.2.77/' inventory.ini   # use your db_private_ip output
ansible all -i inventory.ini -m ping
```

**4. Run the playbook**

```bash
ansible-playbook -i inventory.ini site.yml \
  -e db_pass='<app-db-password>' -e admin_pass='<admin-password>' \
  -e db_ip=<DB_PRIVATE_IP> -e web_ip=<WEB_PUBLIC_IP>
```

Passwords are supplied at run time and are never committed to the repository.

**What the playbook does**

- Database server: adds the MongoDB 7.0 repository, installs MongoDB, binds it to the private IP, creates an admin user and an application user, enables authentication, and configures `ufw` to allow 27017 only from the public subnet.
- Web server: installs Node.js 20, nginx and git, clones the application, writes the backend `.env`, points the frontend at the backend URL, installs dependencies, builds the React app, publishes it through nginx, and runs the backend under pm2.
- nginx is configured with `try_files $uri /index.html;` so React routes such as `/addexperience` work on direct load or refresh.

## Security measures

- SSH to the web server is limited to a single IP via security group.
- The database has no public IP and accepts connections only from the web security group.
- MongoDB authentication is enabled with a least-privilege application user (`readWrite` on one database).
- `ufw` firewalls on both hosts with a default deny policy.
- Root login and password authentication over SSH are disabled; key-based access only.
- Secrets (`.pem` files, Terraform state, tfvars, passwords) are excluded from Git.

## Verifying the deployment

```bash
pm2 status
pm2 logs backend --lines 30
curl http://localhost:3001/hello
```

Then open `http://<WEB_PUBLIC_IP>/` in a browser, add a travel memory, and refresh to confirm it persists in MongoDB.

Screenshots of the deployment are in `docs/screenshots/`.

## Cleanup

The NAT Gateway and EC2 instances incur hourly charges. Destroy everything when finished:

```powershell
cd terraform
terraform destroy
```
